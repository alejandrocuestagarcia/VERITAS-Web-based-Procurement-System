Workflow Documentation

Learn how to build, configure, and define rules for procurement workflows.

info

Veritas procurement workflows are modeled using BPMN standards. Before a workflow can be saved or deployed, its graph structure must pass semantic validation checks.

Validation Requirements

play_circle_outline

Single Start Event

Workflows must contain exactly one Start Event node. It cannot have incoming transitions.

highlight_off

End Events Reachable

Every step must have a path leading to at least one End Event. Dead ends are not allowed.

task_alt

Minimum Complexity

Workflows must include at least one Task step (approval step) between the start and end event.

loop

Cycle Prevention

Gateway-only loops are prohibited as they cause infinite recursion. Loops are allowed only if they pass through at least one human task step.

Understanding Steps

Steps represent physical human tasks in the procurement request pipeline. When a request progresses to a task step, it halts until an eligible user completes the action.

Available User Roles

Role Name Responsibility in Procurement
REQUESTER Initiates requisition requests, adds initial requirements, and makes necessary adjustments or re-submissions if rejected.
PROCUREMENT_OFFICER Responsible for contacting vendors, gathering competitive quotes, uploading documentation, and evaluating vendor bids.
FINANCE_OFFICER Evaluates financial impacts, performs budget audits, verifies fund availability, and performs final monetary approvals.
ADMINISTRATOR Supervises system health and manages overall workflow configurations and overrides.

Custom Instructions / Description

You can provide clear instructions in the task description. These instructions will be directly shown to the assigned role on their dashboard when they take ownership of this step, ensuring standard operating procedures are followed.

Understanding Transition Rules

Transition rules are document and criteria constraints that must be fulfilled before a human task step can be approved. They act as pre-validation barriers to guarantee data integrity.

picture_as_pdf

Required File Types (PDF / CSV / Image)

When checked, the system enforces that at least one file of the specified format (e.g. PDF for signed agreements, CSV for item sheets, or Images for receipts) must be uploaded to the request before completing the task.

store

Minimum Required Vendors

Requires the request to contain quotes from at least the specified number of distinct vendors before it can leave the step. Perfect for enforcing competitive bidding rules (e.g., three quotes rule).

warning

Important Placement Rule: Transition rules can only be placed on paths leaving Task nodes. They cannot be placed on gateway paths, the start event transition, or the end event transition.

Gateway Routing (XOR)

When multiple paths exit an Exclusive Gateway (XOR), the system evaluates Spring Expression Language (SpEL) conditions to decide which path the request should take.

Valid Request Fields

Field Name Type Description
selectedQuoteTotalAmount Number Sum of the selected vendor quote amount.
priority String Priority of the request: 'LOW', 'MEDIUM', 'HIGH'.
totalQuantity Number Sum of all item quantities in the request.
department Department The department of the creating team. Available fields: department.id, department.name, and department budget fields (e.g. department.budget.remainingAmount).
project Project The associated Project. Available fields: project.id, project.name, project.key, and project budget fields (e.g. project.budget.remainingAmount).
requester Requester The Requester (creator) who submitted the request. Available fields: requester.id, requester.name, requester.email, requester.role, requester.isTeamLeader.
budget Budget The associated Internal Budget. Available fields: budget.id, budget.name, budget.totalAmount, budget.committedSpend, budget.actualSpend, budget.safetyBuffer, budget.remainingAmount.
globalBudget Budget The root parent budget. Available fields: globalBudget.id, globalBudget.name, globalBudget.totalAmount, globalBudget.committedSpend, globalBudget.actualSpend, globalBudget.safetyBuffer, globalBudget.remainingAmount.

Allowed Operators & Grouping

Logical Operations (Words Only)
and: Logical AND (e.g. A and B)
or: Logical OR (e.g. A or B)
not: Logical NOT (e.g. not A)
Comparison & Grouping
==, !=: Equal, Not Equal
<, >, <=, >=: Comparators
( ): Grouping expressions (e.g. (A or B) and C)

Example Expressions

High Priority Check
priority == 'HIGH'
Compound Logic (Amount and Priority)
selectedQuoteTotalAmount >= 5000 and priority == 'HIGH'
Team Leader Self-Submission Check
isTeamLeader == true
Project and Global Budget Checks
project.budget.remainingAmount > 1000 or globalBudget.remainingAmount > 50000
alt_route

Default Path: An XOR gateway must always have exactly one default transition with no condition. If none of the other path conditions are met, the request will automatically follow this default path.
